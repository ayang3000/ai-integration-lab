# 学习路线与验收

## 主线与节奏

平台主线：Java AI Gateway + 模型路由，复用后端的多服务接入、治理与观测经验。业务主线：[Archiver Incident Copilot](../features/incident-copilot/spec.md)，检索有权限的公开/合成 Runbook 与日志，给出可追溯引用，必要时调用沙箱中的只读 Job 查询工具或创建本地待审批草稿。网关负责治理，应用负责业务，模型负责生成候选结果。

下面是能力依赖与验收顺序，不是已完成清单，也不要求每阶段耗时相同。按每周 8–10 小时安排的交错实践见[十二周计划](platform-plan.md)；十二周目标是有限作品，不承诺完成全部生产能力。不以“看完文档”作为完成标准。每阶段交付可复现 demo、失败测试、测量结果与一篇短复盘。宽度之外，M3、M5、M6、M8 是建议深入的能力支点。

## 需要补齐的基础知识

- **机器学习常识**：训练/验证/测试拆分、过拟合与数据泄露、precision/recall、向量与相似度、概率与采样。目标是能解释评测结论，不要求先推导完整训练算法。
- **Python**：venv、依赖锁定、typing、pytest、HTTP、JSONL、数据可视化；先写小脚本，别另起一套大后端。
- **集成工程**：HTTP 流、异步与取消、OAuth/OIDC、幂等、分布式追踪、数据库事务。这些是现有后端能力在 AI 场景的延伸。
- **模型能力边界**：幻觉、拒答、上下文限制、工具调用并非执行、不可把推理文本当事实。微调、LoRA、量化与推理部署作为理解选型的选修；先用评测证明需求再投入。

## 每阶段的学习方式

1. 写出输入、输出、权限、状态、副作用、失败策略，再写最小实现。
2. 先用合成数据，不自动导入公司仓库或内部文档到模型/向量库。
3. 手写版本跑通后与官方框架对比，说明节省什么、隐藏什么、增加什么限制。
4. 在 `work/` 写实验草稿，整理后的实验记录放 `docs/learning/`，结果包含环境、数据集版本、命令与真实数值；不预填指标。
5. 按里程碑提交 Git；可用 tag 标记自己的学习 checkpoint，提交由学习者按当前进度自行组织。

## 范围与收敛

中长期 Infra 支线：vLLM、KV Cache、prefill/decode、continuous batching、量化、GPU 推理与 Kubernetes，以可复现的吞吐/延迟实验为产物。可选扩展：多模态、语音、微调、事件驱动批处理。Bandit/PPO 放在规则与统计路由、可靠反馈之后。它们不应阻塞 M1–M9；先把文本模型的端到端质量、权限和成本闭环做好。当前无需云账号或付费服务。
